# Codex 사용량 기록 분석 (2026-10-29)

대상: ~/.codex/sessions 세션 파일 119개, 요청(turn) 1,381개, 모델 호출 단계 6,553개.
스크립트: scripts/analyze-codex.py (숫자만 집계, 대화 내용은 읽지 않음)

## 기록 형식
- `token_usage_record`: 모델 호출 1회의 토큰 (input / cached_input / output / reasoning / total)
- `event_msg.token_count.rate_limits`: 계정 한도 사용률
  - primary: window_minutes=300 (5시간), secondary: window_minutes=10080 (주간)
  - used_percent는 정수(관측된 101개 값 모두 정수) → 해상도 1%

## 수치
| 항목 | 중앙값 | p90 | 최대 |
|---|---|---|---|
| 요청당 단계 수 | 1 | 9 | 181 |
| 요청당 토큰 | 80,346 | 1,420,235 | 24,323,278 |
| 단계당 토큰 | 112,659 | 195,274 | 462,208 |
| 연속 기록 사이 5시간 % 증가 | 1 | 3 | 25 |
| 요청당 5시간 % 증가 (n=300) | 0 | 9 | 91 |

- 입력 토큰 중 캐시 비중: 96.7%
- 1%당 토큰 (단일 세션 구간, 1~3% 증가만): 모델별 약 4만 ~ 23만 → 모델에 따라 약 6배 차이
  - 표본이 작은 모델(6%, 12% 구간)은 신뢰도 낮음

## 설계에 주는 의미
1. 토큰 수로 예산을 잡으면 모델에 따라 실제 % 소모가 크게 달라짐 → Codex는 used_percent를 직접 쓰는 게 정확
2. 6초 사이 로컬 토큰 10만으로 25%가 오른 구간처럼, 로컬 기록에 없는 사용(다른 기기/클라우드 등으로 추정)도 %에 반영됨 → 로컬 토큰 집계만으로는 못 잡음
3. 단계 사이 % 증가는 보통 1~3% → 여유 기본값 3% 근거
4. 동시에 여러 세션이 돌면 % 증가분을 어느 프로젝트에 귀속할지 애매함 → 토큰 비중으로 나누는 규칙 필요
